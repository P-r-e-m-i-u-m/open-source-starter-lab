## Contribution Paths

### Path 1: Claim a Beginner Issue
If you're new to open source, start here. Browse the issue queue for tasks labeled:
- `good first issue`
- `beginner friendly`
- `level: first-pr`

**Steps:**
1. Find an issue that matches your skills
2. Comment to claim it
3. Fork, branch, and work on it
4. Open a PR with your change

### Path 2: Propose a Real Problem
If you've found something broken, confusing, or missing, you can propose it as a new issue.

**Good examples:**
- Missing guides or unclear docs
- Confusing workflows that block new contributors
- Automation gaps (e.g., missing CI checks)
- Accessibility issues on the website
- Repetitive manual tasks that could be automated

**Steps:**
1. Open a new issue using the "Problem Proposal" template
2. Describe the problem clearly and why it matters
3. Suggest a possible solution (optional)
4. Wait for maintainer feedback

**Why propose problems?**
- You help shape the project's direction
- You solve real issues you've actually faced
- You build deeper understanding of the codebase
